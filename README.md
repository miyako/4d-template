# 4d-template

The **template of templates** for 4D repositories. It defines the agent setup every 4D repository should
have — repository instructions plus a reference to the shared skills in
[miyako/skills](https://github.com/miyako/skills) — and nothing else. Real templates are derived from it:

| Derived template | Purpose |
|---|---|
| [miyako/HDI_Template](https://github.com/miyako/HDI_Template) | 4D "How Do I" demo projects |
| [miyako/4d-technote-localisation-template](https://github.com/miyako/4d-technote-localisation-template) | Localisation of 4D technical notes (PDF + demo) |

## What is in it

```
AGENTS.md                                     # repository instructions (placeholders to fill in)
CLAUDE.md                                     # "@AGENTS.md" for Claude Code
.agents/                                      # submodule → miyako/skills, branch dist (the skills)
.gitmodules
.gitignore                                    # the 4dproject skill's canonical .gitignore
.github/instructions/README.md                # when to add a path-scoped instruction file
.github/instructions/example.instructions.md  # format example — delete or replace
.github/workflows/copilot-setup-steps.yml     # Copilot cloud agent: checkout with submodules
.github/workflows/update-skills.yml           # weekly: move .agents to the latest skills, commit if changed
TEMPLATE_CHECKLIST.md                         # checklist for authors of a derived template
scripts/migrate-legacy-repo.py                # converts repositories that use the old layout (see below)
scripts/tests/test_migrate.py                 # its tests (fixture repositories in a temporary folder)
```

- **`AGENTS.md`** is the single entry point for agents (Copilot CLI, VS Code, the cloud agent, Codex; Claude Code
  through `CLAUDE.md`). It says what the repository is, its rules and workflow, and where the skills are.
- **`.agents/`** contains `miyako/skills` as published on its `dist` branch: `.agents/AGENTS.md` (skill selection)
  and `.agents/skills/<name>/SKILL.md`. Agents discover skills in `.agents/skills/` automatically.

## Instructions vs skills

| Kind of knowledge | Where it goes |
|---|---|
| Rules specific to one repository (or to the repositories of one template) | `AGENTS.md`, or `.github/instructions/<topic>.instructions.md` with an `applyTo` glob |
| Reusable know-how: 4D language, forms, CSS, XLIFF, menus, settings, tooling… | a skill in [miyako/skills](https://github.com/miyako/skills) — **never copied** into a repository |

`README.md` is for developers. Copilot model, mode, token or session content never goes into a README.

## Create a new template from this one

1. On GitHub, **Use this template → Create a new repository**, and give it its final name.
2. Clone it with its submodule (see [Clone](#clone)).
3. Fill in `AGENTS.md`: replace every `TODO`, delete the guidance comments, keep the sections marked "keep as is".
4. Add the template's own path-scoped rules to `.github/instructions/` (each with `description` and `applyTo`);
   delete `example.instructions.md`.
5. Keep the `.agents` submodule, `CLAUDE.md` and both workflows. Add the template's own setup steps to
   `copilot-setup-steps.yml` *after* the checkout step, keeping `submodules: true`.
6. Replace this `README.md` with the template's own usage guide, and delete `TEMPLATE_CHECKLIST.md` and
   `scripts/` (they belong to this repository).
7. In **Settings → General**, tick **Template repository**.
8. Add the new template to the table above.

[`TEMPLATE_CHECKLIST.md`](TEMPLATE_CHECKLIST.md) has the full checklist.

## Create a project from a derived template

1. On the derived template (e.g. HDI_Template), **Use this template → Create a new repository**.
   GitHub copies the files, including `.gitmodules` and the `.agents` pointer.
2. Clone the new repository with its submodule (below), then follow its `AGENTS.md` and `README.md`.
3. Fill in the project-specific parts of `AGENTS.md` if the template asks for it.

## Clone

```sh
git clone --recurse-submodules https://github.com/<owner>/<repo>.git
```

or, in an existing clone:

```sh
git submodule update --init .agents
```

`--recursive` is not needed. If `.agents/` is empty, agents cannot see the skills.

## How skills are updated

- `.agents` tracks the `dist` branch of `miyako/skills`, generated by CI from `4d-skills/` on `main`.
- `.github/workflows/update-skills.yml` runs every Monday (and on demand from the Actions tab). It runs
  `git submodule update --remote .agents` and, only if the pointer moved, commits and pushes it to the default
  branch.
- To update by hand: `git submodule update --remote .agents && git commit -m "Update skills" .agents`.
- Never edit files in `.agents/`. Improve the skill in `miyako/skills` instead.
- GitHub disables scheduled workflows after 60 days without repository activity; re-enable the workflow in the
  Actions tab, or run it manually.

## Migrate a repository that uses the old layout

Older repositories carry copies of instructions in `.github/instructions/*.instructions.md`, skills in
`.github/skills/` and a `.github/copilot-instructions.md`. `scripts/migrate-legacy-repo.py` converts them to the
layout above, using the mapping `4d-skills/MIGRATION.json` in miyako/skills. Run
`python3 scripts/migrate-legacy-repo.py --help` for usage, and `python3 scripts/tests/test_migrate.py` for its
tests. Migrate `HDI_Template` and `4d-technote-localisation-template` first: derived repositories are synced
with them.

```sh
# preview (clones, changes and commits in a work folder; never pushes)
python3 scripts/migrate-legacy-repo.py HDI_Foo --dry-run --survey <survey-dir>
# migrate and push
python3 scripts/migrate-legacy-repo.py HDI_Foo TechNote_Bar --push --report-json report.json
# inventory of every surveyed repository (kind, planned action, results of earlier runs)
python3 scripts/migrate-legacy-repo.py --list --survey <survey-dir> --results report.json \
    --list-output docs/MIGRATION_STATUS.md
```
